# Deep Import Subpaths

The SDK publishes eight deep-import subpaths plus the root, enabling consumers to import only the layers they need. Each subpath is dual-format (ESM + CJS) with separate type declarations, built via tsup with one entry per subpath.

## Published Subpaths

**package.json exports map:**

- **`.`** (root) — full barrel: ApiClient, all resource clients, types, errors, guards
- **`./resources`** — resource client classes only (ActivityClient, TimesheetClient, etc.)
- **`./types`** — type definitions without runtime code (Activity, Timesheet, common types)
- **`./errors`** — error hierarchy (ApiError, KimaiConfigError, ResolutionError)
- **`./capabilities`** — zero-import static registry (CAPABILITIES, CAPABILITY_GROUPS, getCapability)
- **`./operations`** — registry-validated invoke layer without MCP runtime (invokeOperation, planInvoke, REFUSAL_CODES)
- **`./mcp`** — MCP tool catalog and effect-split dispatchers (dispatchOperation, EXPOSED, INPUT_CONTRACTS)
- **`./untrusted`** — untrusted content marking helpers (markUntrusted, isUntrusted)
- **`./package.json`** — package metadata

Each subpath exports both import (ESM: `.js`, `.d.ts`) and require (CJS: `.cjs`, `.d.cts`) conditions.

## Tree-Shaking Benefits

Importing from a subpath pulls only that layer's dependencies:

```typescript
// Pulls ONLY the registry (zero runtime imports, pure data)
import { CAPABILITIES, getCapability } from 'node-kimai/capabilities';

// Pulls invoke layer + capabilities, NOT the MCP runtime
import { invokeOperation } from 'node-kimai/operations';

// Pulls MCP dispatch + operations + capabilities + catalog
import { dispatchOperation } from 'node-kimai/mcp';
```

The MCP layer depends on operations, which depends on capabilities—but capabilities has zero imports and can be loaded independently for registry inspection without bringing in SDK code.

## Zero-Import Static Data

**node-kimai/capabilities** exports pure data with no imports:

- `CAPABILITIES: CapabilityRecord[]` — flat array of all operations
- `CAPABILITY_GROUPS` — grouped by resource with plan hashes
- `CAPABILITY_NAMES: readonly string[]` — all operation keys
- `READ_OPERATIONS`, `WRITE_OPERATIONS`, `DESTRUCTIVE_OPERATIONS` — effect-filtered lists
- `getCapability(name)` — O(1) lookup by operation key

This module is generated by `scripts/generate-capabilities.mjs` and has no runtime dependencies. It can be loaded in environments where the SDK itself is unavailable, enabling registry-driven tooling without the client.

## MCP-Independent Operations

**node-kimai/operations** provides the registry-validated invoke layer without any MCP runtime dependency. This enables:

- Direct invocation in non-MCP hosts (CLI tools, test harnesses)
- Registry validation without MCP schema libraries
- Planning and dry-run simulation without transport

The rule this subpath enforces: validation and governance live in exactly one place. The MCP layer (`./mcp`) adds only the effect boundary and delegates to `./operations`.

## Dual-Format Support

Every subpath ships both ESM and CJS artifacts with matching type declarations:

- **ESM:** `.js` (code) + `.d.ts` (types)
- **CJS:** `.cjs` (code) + `.d.cts` (types)

Package marked `"sideEffects": false` enables aggressive tree-shaking in bundlers. Tsup generates four outputs per entry: ESM/CJS × code/types.

## Published-Surface Guard

`scripts/public-surface.mjs` verifies the published surface against the built tree:

1. **Exports alignment** — package.json exports and tsup entries describe the same subpath set
2. **File existence** — every condition target (import/require × types/default) exists in dist/
3. **Load test** — each subpath successfully loads via require() (CJS) and import() (ESM)
4. **Zero runtime deps** — no dependencies field, no non-builtin bare specifiers in dist/

This guard runs in `npm run verify` and prevents shipping a broken export map or missing artifacts.

## Build Configuration

Tsup entries mirror the subpaths:

```javascript
{
  entry: {
    'index': 'src/index.ts',
    'resources/index': 'src/resources/index.ts',
    'types/index': 'src/types/index.ts',
    'errors': 'src/errors.ts',
    'capabilities': 'src/capabilities.ts',
    'operations/index': 'src/operations/index.ts',
    'mcp/index': 'src/mcp/index.ts',
    'untrusted': 'src/untrusted.ts',
  },
  format: ['esm', 'cjs'],
  dts: true,
}
```

Each entry produces four dist/ files. The root barrel (`src/index.ts`) re-exports from all layers, enabling single-import convenience when tree-shaking is not a concern.

## Usage Patterns

**Full SDK import:**
```typescript
import { ApiClient } from 'node-kimai';
```

**Tree-shaken type-only import:**
```typescript
import type { Timesheet } from 'node-kimai/types';
```

**Registry-only inspection (zero SDK code):**
```typescript
import { CAPABILITIES, getCapability } from 'node-kimai/capabilities';
```

**MCP-independent invoke:**
```typescript
import { invokeOperation, planInvoke } from 'node-kimai/operations';
```

**MCP dispatch with effect boundary:**
```typescript
import { dispatchOperation } from 'node-kimai/mcp';
```
